An Emacs package that wraps [[https://github.com/larksuite/cli][lark-cli]] to bring Lark/Feishu into Emacs.
Transient menus for command dispatch, mu4e-style mail, dired-like drive
browsing, org-table spreadsheets, and async execution throughout.

* Quick Start: First-Time Setup

This section walks you through initial configuration, authentication,
and pulling up your calendar — all from within Emacs.

** Step 1: Configure lark-cli (one-time)

Before elark can talk to Lark, you need to register an app.
Run this in your terminal (or use =M-x shell=):

#+begin_src shell
lark-cli config init
#+end_src

This is an interactive prompt that asks for:

1. *Brand*: choose =feishu= (China) or =lark= (international)
2. *App ID & App Secret*: from the [[https://open.feishu.cn/app][Feishu Open Platform]] (or [[https://open.larksuite.com/app][Lark Developer Console]])
   - Go to the console, create an app (or use an existing one)
   - Copy the App ID and App Secret
3. The CLI stores credentials locally in =~/.config/lark-cli/=

If you prefer non-interactive setup:

#+begin_src shell
echo "YOUR_APP_SECRET" | lark-cli config init \
  --app-id cli_xxxxxxxxxxxx \
  --app-secret-stdin \
  --brand feishu
#+end_src

Verify:

#+begin_src shell
lark-cli config show
#+end_src

** Step 2: Authenticate (OAuth login)

Now authenticate your Lark user account. You can do this either from the
terminal or from Emacs:

*** Option A: From Emacs

#+begin_src
M-x elark-auth-login
#+end_src

Or use the keybinding: =C-c l l= then press =L= (Login).

This will:
1. Call =lark-cli auth login --no-wait= in the background
2. Open your browser to the Lark authorization page
3. Poll automatically until you approve in the browser
4. Show "Lark: login successful!" in the echo area

*** Option B: From terminal first

#+begin_src shell
lark-cli auth login --domain calendar
#+end_src

The =--domain= flag requests scopes for a specific domain. Available
domains: =calendar=, =task=, =im=, =mail=, =contact=, =docs=, =drive=,
=base=, =sheets=, =wiki=, =vc=, =approval=, =event=, =minutes=, or =all=.

You can request multiple domains:

#+begin_src shell
lark-cli auth login --domain calendar,task,im
#+end_src

Or request everything:

#+begin_src shell
lark-cli auth login --domain all
#+end_src

*** Verify authentication

From Emacs:

#+begin_src
M-x elark-auth-status
#+end_src

Or: =C-c l s=

This shows your login status in the echo area. You should see something
like "Lark: authenticated as Your Name (your-tenant)".

From terminal:

#+begin_src shell
lark-cli auth status
#+end_src

** Step 3: View your calendar

Now the fun part:

#+begin_src
C-c l a
#+end_src

Or: =M-x elark-calendar-agenda=

This fetches today's agenda and displays it in a =*Lark Agenda*= buffer:

#+begin_example
Daily Standup
  Start:      2026-04-12 09:00

  Organizer:  Alice
  RSVP:       accept

Sprint Planning
  Start:      2026-04-12 10:00
  End:        2026-04-12 11:00
  Location:   Room 301
  Organizer:  Bob
  RSVP:       accept

1:1 with Manager
  Start:      2026-04-12 14:00
  End:        2026-04-12 15:00
  Organizer:  Carol
  RSVP:       tentative
#+end_example

* AI Layer

elark includes an AI-native orchestration layer that turns natural-language
prompts into multi-step lark-cli execution plans.  Instead of remembering
which commands to chain together, you describe what you want and the AI
figures out the steps.

** How it works

1. You type a prompt (e.g., "what's on my plate today?")
2. elark selects the relevant lark-cli skill files (=SKILL.md=) based on
   keywords in your prompt
3. The skills + your prompt are sent to an LLM, which returns a JSON
   execution plan
4. The plan is shown in a review buffer — you can inspect, remove steps,
   or cancel
5. On confirmation, elark executes the CLI commands (in parallel where
   possible), collecting results
6. If the plan includes a synthesis step, results are sent back to the LLM
   for a human-readable summary
7. The final output is rendered in a buffer

Write operations (create, update, delete, send) are flagged in the plan and
require explicit confirmation before execution.

** Prerequisites

- An LLM backend: a local ACP agent such as Claude Code or Gemini CLI via
  [[https://github.com/xenodium/acp.el][acp.el]] (recommended, the default — no API key), [[https://github.com/karthink/gptel][gptel]], or any
  OpenAI-compatible HTTP endpoint
- lark-cli skills installed in =~/.agent/skills/=:

#+begin_src shell
npx skills add larksuite/cli -g -y
#+end_src

** Setup

*** With a local ACP agent (default, no API key)

The default backend drives a locally installed [[https://agentclientprotocol.com][Agent Client Protocol]]
agent — the same mechanism [[https://github.com/xenodium/agent-shell][agent-shell]] uses — so the agent's own login
is reused and no API key is needed.  Requires the [[https://github.com/xenodium/acp.el][acp.el]] package and an
ACP agent binary:

#+begin_src shell
npm install -g @zed-industries/claude-code-acp   # Claude Code adapter
#+end_src

#+begin_src emacs-lisp
;; Nothing to configure: `elark-ai-backend' defaults to `acp' and the
;; default agent is claude-code-acp.

;; To use Gemini CLI instead:
(setq elark-ai-acp-command "gemini"
      elark-ai-acp-command-params '("--experimental-acp")
      ;; Gemini ignores the session _meta systemPrompt extension, so
      ;; send elark's system prompt inline with the user message:
      elark-ai-acp-system-prompt-placement 'inline)
#+end_src

The agent process is started on first use and kept alive;
=M-x elark-ai-acp-shutdown= kills it.  Each LLM call runs in a fresh
ACP session, and the agent's own tools are disabled — it acts purely
as the text engine behind elark's agent loop.

*** With gptel

#+begin_src emacs-lisp
(use-package gptel
  :config
  ;; configure your preferred provider
  (setq gptel-model 'claude-sonnet-4-20250514))

(setq elark-ai-backend 'gptel)
#+end_src

*** With a raw HTTP endpoint

#+begin_src emacs-lisp
(setq elark-ai-backend 'http
      elark-ai-http-endpoint "https://api.openai.com/v1/chat/completions"
      elark-ai-http-api-key "sk-...")
#+end_src

Or set the =ELARK_AI_API_KEY= environment variable instead of hardcoding the key.

** Examples

*** Standup report

#+begin_src
C-c l i  "what's on my plate today?"
#+end_src

The AI generates a plan:

#+begin_example
Lark AI -- Execution Plan
----------------------------------------

  [0] Fetch today's agenda  (read-only)  [group 1]
      lark-cli calendar +agenda
  [1] Fetch open tasks  (read-only)  [group 1]
      lark-cli task +get-my-tasks
  [2] Summarize schedule and tasks  (AI synthesis)

----------------------------------------
  RET Execute  x Remove step  q Cancel
#+end_example

Steps 0 and 1 run in parallel (same group).  After execution, the LLM
synthesizes results into:

#+begin_example
## 2026-04-13 Sunday

### Agenda
| Time        | Event              | Organizer | Status   |
|-------------+--------------------+-----------+----------|
| 09:00-09:30 | Daily Standup      | Alice     | accepted |
| 14:00-15:00 | 1:1 with Manager   | Carol     | tentative|

### Open Tasks
- [ ] Review PR #142 (due: today)
- [ ] Update API docs (due: Apr 14)

### Notes
- No scheduling conflicts
- Free slots: 10:00-14:00, 15:00-18:00
#+end_example

Or use the dedicated command: =M-x elark-ai-workflow-standup=.

*** Meeting summary

#+begin_src
C-c l i  "summarise my meetings this week"
#+end_src

The AI chains =vc +search= -> =vc +notes= -> synthesis, producing a
structured report of all meetings with their notes and action items.

Or: =M-x elark-ai-workflow-meeting-summary=.

*** Schedule a meeting

#+begin_src
C-c l i  "set up a 30min sync with Alice next Tuesday afternoon"
#+end_src

The AI plan:

#+begin_example
  [0] Search contact "Alice"  (read-only)
  [1] Find available time slots  (read-only)
  [2] Check room availability  (read-only)
  [3] Create calendar event  CAUTION writes
#+end_example

Step 3 is marked as a side-effect and will prompt for confirmation
before executing.

Or: =M-x elark-ai-workflow-schedule=.

* Troubleshooting

** "Cannot find lark-cli executable"

lark-cli is not on your =PATH=. Either:

- Install it: =npm install -g @larksuite/cli=
- Set the full path: =(setq elark-cli-executable "/path/to/lark-cli")=

** "Lark: not authenticated"

Run =M-x elark-auth-login= or authenticate from terminal:

#+begin_src shell
lark-cli auth login --domain all
#+end_src

** Empty agenda / "no events found"

1. Check you have calendar scopes: =lark-cli auth check --scope calendar:readonly=
2. Try from terminal first: =lark-cli calendar +agenda=
3. If the terminal works but Emacs doesn't, enable debug logging:
   =(setq elark--debug t)= and check the =*elark-log*= buffer

** Permission errors

Some operations require specific scopes. Re-login with the needed domain:

#+begin_src shell
lark-cli auth login --domain calendar,task
#+end_src

** Debugging

Enable debug logging to see all CLI invocations:

#+begin_src emacs-lisp
(setq elark--debug t)
#+end_src

Then check =*elark-log*= buffer (=C-x b *elark-log*=) to see every command
that elark runs, including arguments and exit codes.

* Architecture

#+begin_example
elark.el                         Entry point, defgroup, prefix keymap, load-path setup

core/
  elark-core.el                  Process management, JSON parsing, CLI debug line stripping
  elark-auth.el                  OAuth device-code login, status, identity switching
  elark-transient.el             Top-level transient dispatch menu

ui/
  elark-ui.el                    Shared presentation helpers (loading spinner)

domain/
  elark-calendar.el              Calendar: agenda, events, create, free/busy, RSVP
  elark-tasks.el                 Tasks: list, create, complete, subtasks, tasklists
  elark-im.el                    Messenger: chats, messages, send, reply, events
  elark-mail.el                  Mail: mu4e-style inbox, shr HTML rendering, compose
  elark-docs.el                  Docs: search, fetch, create, update, media operations
  elark-drive.el                 Drive: dired-like browser, upload/download, owner names
  elark-sheets.el                Sheets: org-table read/write, create, find, export
  elark-contact.el               Contacts: user lookup, search, name resolution cache
  elark-meetings.el              Meetings: search, notes, recording with download links
  elark-whiteboard.el            Whiteboard: create and update whiteboards

ai/
  elark-ai.el                    AI: prompt -> plan -> execute -> synthesize -> present
  elark-ai-skills.el             AI: skill registry, loader, system prompt assembly
  elark-ai-context.el            AI: buffer context extraction for all domain modes
  elark-ai-llm.el                AI: LLM backend dispatch (gptel / acp / http)
  elark-ai-acp.el                AI: ACP agent backend (Claude Code, Gemini CLI, ... via acp.el)

test/
  elark-*-test.el                ERT tests for each module

demo/
  elark-native-ui-demo.el        Runnable magit-section / tabulated-list UI preview
  elark-*.mp4                    Domain screen-recording sources (hosted copies
                                are embedded in the Demos section)
#+end_example

All CLI calls funnel through =elark--run-command= (async) or
=elark--run-command-sync=.  Output is =--format json= by default, parsed
with =json-parse-string=.  CLI debug lines (=[cmd +sub]= prefixes and
=tip= lines) are automatically stripped before JSON parsing.

=elark.el= automatically adds =core/=, =ui/=, =domain/=, and =ai/= to the
=load-path= at load time, so a single =(add-to-list 'load-path "/path/to/elark")=
is sufficient.
